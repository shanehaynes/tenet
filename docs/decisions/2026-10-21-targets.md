# Targets: the thing under test

**Decision.** The executor talks to a `Target`: either a model with the policy as its system prompt (the default, gpt-6-luna) or an HTTP agent that implements `POST {url} {message, conversation_id, reset, agent}` and returns `{reply, actions, usage, meta}` (architecture §4.6). The HTTP target is the bridge into Shane's HW5 agent team (`POST /tenet/ask` on a `tenet-bridge` branch of the Homework5 repo). HTTP targets run at concurrency 1 with a database reset per scenario; their tool calls are stored with the transcript and shown to the judge; their reported usage is logged with `stage: "target"` and flagged as reported by the target. The `Target` type is in the schemas from day one so Saturday's HTTP work adds a branch, not a reshape.

**Why.** The professor's Tier 3 bar is "run it on something real": real rules, real agents, known ground truth. The HW5 agents have rules enforced by tools and rules enforced only by prompt, which gives a ground-truth column to set beside Tenet's verdicts. If the bridge is not working by Saturday 10:00, the HW5 rules run as a plain policy against gpt-6-luna and the report says so.
