# Prefix calibration and the executor preamble

**Decision.** The prefix-budget test now estimates tokens as characters ÷ 5.2 with a floor of 1,050 (`src/core/model/tokens.ts`), replacing characters ÷ 4 with a floor of 1,100. The executor preamble gained four paragraphs: the systems the assistant can act through, stating in the reply any action it takes, dates and amounts, and reply language. `npm run measure:prefixes` sends each static prefix twice and records real prompt tokens and cache hits in `docs/evidence/tokenomics/prefix-measurement.md`.

**Why.** The first live smoke test on 2026-10-21 showed the executor prefix on the demo policy was 884 real prompt tokens, so it was not cached (0 cached on repeat), even though the chars ÷ 4 test said 1,139. Real text ran 4.5–5.2 characters per token. The executor is about 75 of the ~180 calls in a demo run, so an uncached executor prefix would have erased most of the caching result in the tokenomics section. After the change the prefix measures 1,075 tokens with 1,072 cached on repeat, and the classifier prefix 1,497 with 1,494 cached, which also proves the gateway passes caching through. The added paragraphs are useful in their own right: a model under test that believes its actions are real makes a real choice when it refuses, and a reply that states the action taken gives the judge evidence for model targets, which have no tool-call log.
